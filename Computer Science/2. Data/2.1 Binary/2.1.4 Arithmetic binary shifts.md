# 2.1.4 Arithmetic binary shifts

### Left arithmetic shifting

Shifts are **bitwise operations**: they operate on each bit in a pattern. In a left shift, each bit moves one place left, the MSB is discarded, and a 0 is inserted at the right (LSB). For a positive value, this multiplies by 2 if no significant bit is lost.

```text
00010111  (23)
00101110  (46) after a one-bit left shift
```

Left arithmetic shifting works in the same way as left logical shifting.

### Right arithmetic shifting

In a right arithmetic shift, each bit moves one place right and the MSB is copied into the vacated position. This preserves the sign of a two’s-complement value and has the effect of dividing by 2, rounding down for negative odd values.

```text
00010111  (23)
00001011  (11) after a one-bit right shift
```

When shifting more than once, copy the MSB into each newly vacated position. For positive values this gives the same result as a logical right shift; the difference matters for negative values.

### Signed integers

Consider three consecutive left arithmetic shifts of the 8-bit two’s-complement value −22 (`11101010`):

| Shift | Bit pattern | Signed value |
|---|---|---:|
| Start | `11101010` | −22 |
| 1 left shift | `11010100` | −44 |
| 2 left shifts | `10101000` | −88 |
| 3 left shifts | `01010000` | +80 (overflow) |

The mathematical result after three shifts should be −176, which is outside the 8-bit signed range. The bit pattern has overflowed, so it no longer represents the expected result.

### Overflow

We've looked at overflows before. An overflow error is when the result of a calculation is too large for the space allocated for it. We've just seen the effect that overflows have when performing shifts.
