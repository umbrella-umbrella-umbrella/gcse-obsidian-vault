# 2.1.2 Two complement - Part 1

### Unsigned integers

Up to now, you have been working with unsigned integers. These are whole numbers that are positive (0 or higher). But what if you want to represent negative numbers? In what situations might you need to represent negative numbers?

### Negative numbers

Computers cannot recognise the symbols `+` or `−`, so signed numbers need to be represented in binary. One method is **sign and magnitude**: the most significant bit (MSB) is used as a sign bit (0 for positive and 1 for negative), while the remaining bits represent the magnitude. This method has two representations for zero.

Two’s complement uses the MSB as a negative place value. In an 8-bit number, the place values are:

| Place value | −128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Bit pattern for −115 | 1 | 0 | 0 | 0 | 1 | 1 | 0 | 1 |

The value is −128 + 8 + 4 + 1 = **−115**. In 8-bit two’s complement, the range is **−128 to +127**. There is only one representation of zero.

### Converting positive values to denary

Positive values use the same place values as unsigned binary, with a leading 0 to show that the value is positive. For example:

| Place value | −128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Bit pattern | 0 | 0 | 0 | 0 | 0 | 1 | 1 | 1 |

The value is 4 + 2 + 1 = **+7**. Keep the positive sign because this is a signed integer.

### Converting negative values to denary

For negative values, use the two’s-complement place values. For example, `11111011` represents −5:

| Place value | −128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Bit pattern | 1 | 1 | 1 | 1 | 1 | 0 | 1 | 1 |

The value is −128 + 64 + 32 + 16 + 8 + 2 + 1 = **−5**.

### Conversion method

You've looked at binary to denary conversions for two's complement, but how do you go back the other way? For positive numbers, it's just the same as you've done previously using subtraction. For negative numbers, there are some extra steps:

- convert the unsigned equivalent into 8-bit binary
- flip the bits (each 1 becomes a 0 and vice versa)
- add 1 (arithmetically, not appending).

### Worked example

Convert −22 to 8-bit two’s-complement binary:

1. Convert the magnitude, 22, to 8-bit binary: `00010110`.
2. Flip every bit: `11101001`.
3. Add 1: `11101010`.

Therefore, −22 is `11101010` in 8-bit two’s-complement.
