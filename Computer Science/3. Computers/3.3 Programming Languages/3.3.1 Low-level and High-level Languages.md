# 3.3.1 Low-level and High-level Languages

### Learning objectives

In this lesson you will learn to:

- Define what is meant by the terms ‘low-level language' and ‘high-level language'

- Explain why each processor has its own unique instruction set

- Describe how writing a program in a low-level language differs from writing one in a high-level language

- Compare features of low-level and high-level languages and identify tasks for which each is best suited.

### Instructions

- An instruction set is all the different instructions a microprocessor (CPU) can execute.

- The instructions are stored in memory as binary patterns.

- The instructions are fetched, decoded and executed by the CPU.

### Machine code

- The binary patterns, representing a program, are called machine code.

- Machine code sits as close to the hardware as possible.

- While it is quite simple for the CPU to execute, it's quite a challenge for humans to understand.

### Assembly code

- As with machine code, assembly code sits very close to the hardware.

- One line of assembly code generates one instruction in machine code.

- What does this program, written in assembly code, do? MOV x0, #12 MOV x1, #8 ADD x2, x0, x1

- This is easier to understand than binary, as the mnemonics (short abbreviations) are similar to English.

### Define ‘low-level' programming language

- Sits very close to the computer's hardware

- Either machine code or assembly language

- Consists of binary codes or simple mnemonics that represent the binary codes.

### Define ‘high-level' programming language

- Abstracted away from the hardware

- The programmer does not need to understand ‘how' the computer works

- Uses English-like statements

- Requires a translator to convert the source code to machine code

- Some examples are Python, Java, JavaScript, C++ and C.

### Each microprocessor has its own unique

instruction set

- Microprocessor architecture is designed with a limited set of electronic components.

- An instruction set is an abstraction that defines the behaviours of these specific electronic components.

- For example, MOV x0, #12, is the abstract instruction that causes the value of 12 to be moved into register number 0.

- For each allowable and defined behaviour, there is an abstract instruction. Each microprocessor with a unique set of components requires a different unique set of instructions.
