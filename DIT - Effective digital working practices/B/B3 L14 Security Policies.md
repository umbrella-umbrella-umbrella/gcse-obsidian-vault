# Security policies
- A **security policy** is a set of written rules and guidelines explaining how an organisation protects its data, systems, and users from security threats.
- Policies can define responsibility and explain how staff should report concerns and issues.

### Examples

| Policy or guideline | Purpose |
| --- | --- |
| Password policy | Rules for creating, using, and protecting passwords. |
| Acceptable Use Policy (AUP) | Explains how people may use the organisation's IT systems, internet, software, and devices, and what behaviour is prohibited. |
| Device hardening parameters | Security settings and configurations used to reduce vulnerabilities and prevent unauthorised access. |

### Disaster recovery plan
- A documented plan for restoring systems, data, and normal operations after a serious incident such as a cyber attack, data loss, system failure, natural disaster, or power cut.

| A disaster recovery plan should specify | Purpose |
| --- | --- |
| Responsibilities | Clear ownership supports fast recovery. |
| Staff dos and don'ts | Staff behaviour matters during an incident. |
| Backup process | Explains what is backed up and how. |
| Recovery timeline | Defines expected recovery times. |
| Alternative provision or location | Allows operations to continue if the main site is unavailable. |

- **Before an incident:** Prepare measures such as keeping backups in another location.
- **During an incident:** Follow response measures, such as using a backup generator during a power cut.

### Actions after an attack
1. Investigate the severity and nature of the incident.
2. Respond by informing or updating stakeholders and authorities.
3. Manage the incident through containment.
4. Recover using the disaster recovery plan.
5. Analyse the incident and update policies and procedures.
